# H9 (freeze): format 1.0 is frozen as `main` writes it

- Asked: 2026-10-21, `ROADMAP.md` "What needs the owner" (H9); answered in part on 2026-10-27
  (`rulings/2026-10-27-H9.md`: 4.1.0 ships first as a testers-only preview); asked again on
  2026-11-09 by the #865 session, with every remaining decision of the freeze, after #963 settled
  the last format rows of `docs/STORAGE-DELTA-2026-10-21.md` §2.15.
- Options: freeze 1.0 as `main` writes it today, with the preview's projects opening in 1.0; or
  wait for the Markdown import (#967) and the `.tc/materialized.json` change (S3) and freeze
  after them; or freeze with the first preview (`v4.1.0-preview`) as the older reader.
- Answer: the owner, in the #865 interview on 2026-11-09, in these words:
  1. **Format 1.0 is frozen as `main` writes it today**: major 1, minor 0 (`FORMAT_MAJOR`,
     `FORMAT_MINOR` in `crates/tc-journal/src/format.rs`), with #963's removals. The freeze takes
     effect when the marker `fixtures/capsules/1.0/FROZEN` merges. H9's name `1.0-draft` for the
     preview's set is retired: the preview wrote 1.0 and its projects open in 1.0.
  2. **No `ImportSource::Markdown` in 1.0.** Nothing writes it. #967 (milestone 4.2.0) is the
     writer and adds it as a format minor.
  3. **`.tc/` is not part of the format.** `.tc/materialized.json`, `.tc/heads/*.bin` and the
     pending header are local to one computer, git-ignored and never exchanged (STORAGE §3.6, §1
     "LOCAL ONLY"). S3 may change them without a version. Only `ingredients/tc/format.json` and
     the shared byte forms (change lines, packs, exchange files, sidecars, derived files) are
     frozen.
  4. **Every version leaves a capsule set**, minors included; a minor's set may be one small
     project that exercises the new field.
  5. **The older reader is the build at the freeze**, shipped to named testers as
     `v4.1.0-preview2` under H9's testers-only rule. Not the first preview, which is five weeks
     of fixes behind.
  6. **Out of scope**: importing projects from the JavaScript tC 4.0 (import, not format);
     Door43 edits by other tools (H18); the fold cache (`INDEX_VERSION`, local, rebuilt on
     open); publishing the public 4.1.0 (its own issue).

## The rule

- Format 1.0 is what `main` writes at the commit the marker `fixtures/capsules/1.0/FROZEN`
  names: `format.json` with major 1 and minor 0, the change-line encoding, the record kinds,
  fields and causes of minor 0, the pack and pending framing, the exchange file's comment, the
  sidecars' `schemaVersion` and the derived files' bytes (`docs/STORAGE.md` §12.3 lists them).
- From that merge on, a change to any pinned byte needs a new format version, its own capsule
  set and its own `FORMAT_PINS` row (§12.2 rule 7, §12.3). `TC_JOURNAL_BLESS` and
  `TC_WRITE_PROBE` refuse to rewrite a pinned sample while the current version is frozen.
- `.tc/` is outside the format: its files change without a version.
- `ImportSource::Markdown` is not in 1.0; #967 adds it as a minor, and older apps read a project
  that holds it read-only (rule 7).
- The nine sample projects of 1.0 (`fixtures/capsules/1.0/`) are generated from the
  repository's fixtures by `cargo run -p tc-corpus --example capsule -- write 1.0
  fixtures/capsules/1.0`, never from a person's project, and nobody changes them afterwards.
- The build at the freeze is the older reader: the owner tags it `v4.1.0-preview2`, publishes
  the draft release to named testers only (H9), and CI's `format-older-reader` job drives that
  build against folders the current build writes on every merge-queue run.

## Effect for translators

A project saved by the preview, or by any later version, opens in every later version with
every verse, alignment, check decision, comment, conflict and history entry as it was. A
teammate on the older preview who opens a project a newer version wrote sees it read-only with
"needs a newer app", or is refused before anything is written when the major is newer; the
project is never called damaged (tC4 RISKS #10 and #46).
