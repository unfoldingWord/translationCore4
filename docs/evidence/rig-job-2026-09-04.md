# The rig job: the rig-gated suites run in CI, and the gate can fail (2026-09-04)

**Question:** can a machine with no assembled Pankosmia desktop-app build assemble the rig
from the pinned inputs, seed it, start it, and run every rig-gated suite through
`npm run prove`? And does `prove` refuse the rig suites when that rig is no longer pristine?
This is L-1b of #154 (`docs/plans/LEGIBILITY.md` §3 and §5).

**Method:** a detached worktree of `main` `ff20e22` plus the L-1b change set, on macOS,
Node v22.14.0. The workspace rig was stopped by PID. Then, in the worktree, in order:

```
npm ci && (cd conformance && npm ci) && npm run build
zsh dev-env/scripts/setup-from-pins.zsh
zsh dev-env/scripts/cache-resource.zsh unfoldingWord/en_ult v89 84c73ba00fc8a95a9033f9efb14bb905a2a52ee4
zsh dev-env/scripts/seed.zsh
zsh dev-env/scripts/run.zsh            # background, 127.0.0.1:19998
RIG_REPOS=<worktree>/dev-env/state/work/repos npm run prove      # positive control
RIG_REPOS=<worktree>/dev-env/state/work/repos npm run prove      # negative control, same rig
```

The workflow `.github/workflows/rig.yml` runs these steps on `ubuntu-24.04`.

**Inputs:** `resource-core` `54802be`, `webfonts-core` `eb52ccd`, `desktop-app-template`
`4cb7576` (the pins of `scripts/package-desktop.zsh`); the server built from
`dev-env/server` (pankosmia-web 0.18.5, `99fd9bea8a9f3d14ac6a61f8e2213f1c5d42ed2a`);
`conformance/sample-burrito`; the `en_ult` v89 export, whose declared revision matched the

`lint` failed in this first run: `eslint .` reached the assembled `dev-env/app-resources/`
and `dev-env/upstream/` trees (upstream and built JavaScript, 834 errors). The change set
adds those directories to the ESLint ignore list and to `.gitignore`; `npm run lint` then
exits 0. Every other suite passed. `(dirty)` names the uncommitted change set itself.

**Result, negative control:** the positive run left twelve extra repositories under
`_local_/_local_` (`rt_burrito`, `rig_*`, `inc1*`, `j61js_*`). The second `prove` exited
non-zero, and each rig suite skipped with the same reason:

```
SKIP  conformance:transport  REFUSED: rig not pristine — extra repos under _local_/_local_: ... (dev-env/scripts/stop.zsh; seed.zsh; run.zsh)
SKIP  conformance:roundtrip  REFUSED: rig not pristine — ...
SKIP  vitest:rig             REFUSED: rig not pristine — ...
commit ff20e22 (dirty) · rig 0.18.5 (99fd9be) pristine=false
PROVE FAILED
```

The workflow's negative-control step requires exactly this: a non-zero exit, the line
`rig suites: REFUSED`, and in the manifest every `needsRig` suite with `ran=false` and a
`skipped` reason that starts with `REFUSED`.
